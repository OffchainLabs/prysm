### Fixed

- A resync attempt that fails or ends with the node still behind its peers no longer re-marks the node as synced. Previously a node that fell behind and failed to resync would keep advertising itself as healthy via `/eth/v1/node/health` and `/healthz`, so load balancers kept routing validator duties to it while it served stale data. The regular sync service now also keeps retrying resync while the node remains behind, instead of never re-attempting after a failed resync. Sync status is measured against peers rather than the wall clock, so a node at the head of a network that has stopped producing blocks keeps reporting healthy.
