### Added

- New `beacon-chain/p2p/peerscoring` package: a self-contained peer grey-listing service replacing the bad-responses, peer-status and gossip scorers. Grey-listing is an any-aspect verdict (bad-response threshold, terminal status validation error, gossip score threshold); bad responses carry a granular source enum and reason; the libp2p gossip score, behaviour penalty and topic snapshots are mirrored for the debug RPC.
- New `peerscoring.GossipRejectionsStore`: records every gossip message our topic validators reject (peer, topic, agent, reason, time) to debug which peers send invalid messages on which topics — pure observability, feeding neither scoring nor grey-listing. Per peer it serves agent → rejections and topic → rejections views; only the most recent 100 rejections are retained per peer, and peers pruned from the peer store are dropped.
- New peer-scoring debug endpoints under `/prysm/v1/node`: `GET /peers/{peer_id}/scoring` returns one peer's full scoring picture — agent, connection state, direction, `connected_at` (when the peer last connected) and `tenure` (human-readable connection duration for currently connected peers), bad responses (source, reason, time), rpc status incl. the chain validation error, the mirrored gossip score with every recorded gossip rejection, and every firing grey-list verdict (per aspect and IP colocation, in `grey_list_details`) with its reason, trusted-peer exemption, and estimated time to white-listing. `GET /peers/scoring` lists the same for every tracked peer, grey-listed peers first then by standing strike count (`sort=bad_responses`, default) or `sort=peer_id`, filterable by `greylisted`, `agent` (substring) and `source`. Per-topic gossip counters are opt-in on both via `include_topic_scores=true` (default off). `GET /peers/scoring/agents` aggregates per agent; `GET /peers/scoring/config` returns the grey-listing thresholds, decay and context; `GET /gossip/rejections` queries retained gossip rejections across peers (filters: `topic`, `agent`, `peer_id`, `since`), and `GET /gossip/rejections/summary` counts them per topic, agent, reason or peer. All list endpoints paginate via `limit`/`offset`.
- `peers.Status` now stamps each peer's connection time (`ConnectedAt`, reset on reconnect); it drives tenure-based eviction and is exposed in the scoring debug API.
- Excess-inbound-peer pruning now also protects peers needed for PeerDAS data-column subnet coverage (post-Fulu, for our sampling/custody subnets) and active sync-committee subnet coverage, alongside the existing attestation-subnet protection, all under `--minimum-peers-per-subnet`.

### Changed

- Peer grey-listing and peer chain-status tracking now live in `p2p/peerscoring`, wired directly into the p2p service; `peers.Status` no longer exposes scoring or badness APIs.
- The block provider scorer is now the self-contained `p2p/blockprovider.Selector` (it is a sync peer-selection mechanism, not scoring), owned by the p2p service and reached via `BlockProviderSelector()`; it keeps its own state instead of writing into `peerdata.PeerData`, drops fully-decayed idle entries, and is pruned alongside the peer store.
- The `p2p_peer_count{state="Bad"}` metric now counts the full grey-list verdict instead of only bad-responses badness.
- Peer scoring state is evicted when the peer store prunes a peer (grey-listed peers are retained), and only the most recent bad-response strikes are kept per peer (default 25, configurable), bounding peer scoring memory.
- The gossip score mirror is reconciled against each libp2p inspector report: peers libp2p no longer tracks have their gossip state cleared (entries with no other scoring state are dropped), so a gossip grey-listing now expires with libp2p's score retention window instead of persisting until restart.
- Grey-list verdicts now carry the reason (which aspect fired and why) instead of a generic "peer is grey-listed" error, improving disconnect and refusal logs.
- Inbound status exchanges that fail fork-digest validation now store the failed verdict, grey-listing wrong-network peers the same way the outbound status path does (previously they were only disconnected and could keep reconnecting).
- The highest known peer head slot (used by the sync-status health check) now only counts statuses that passed validation, so a peer advertising a bogus head slot can no longer wedge the node's reported sync status.
- Excess-inbound-peer eviction no longer ranks peers by a composite score. After the subnet-coverage filter, grey-listed candidates are evicted first; the rest are evicted uniformly at random, with the oldest quarter by connection time moved to the back of the eviction order (youngest-tenured first) — tenure is costly to fake, making eviction resistant to eclipse-style targeting — and 5% of pruning rounds ignore tenure so it never confers permanent immunity. Sub-greylist strikes no longer influence eviction order.
- Excess-inbound-peer pruning applies the subnet-coverage filter before trimming to the prune quota (previously protected peers silently shrank the quota, leaving the node over its limits), preserves the eviction-priority order through a stable subnet-count sort, and also triggers when only the inbound limit (not the total limit) is exceeded. `peers.Status.PeersToPrune` is now `PruneCandidates`, returning the full ordered candidate list and the prune count.
- Peer-store garbage collection of disconnected peers (`Prune`) now forgets peers with the fewest standing strikes first, keeping the memory of the worst misbehavers the longest.
- Trusted peers are protected from libp2p connection-manager trimming for as long as they remain trusted.

### Removed

- Removed the composite peer score entirely: `Scorer.Score` and the per-aspect score contributions, the scoring weights and their options, the `score_details` query flag and `composite_score`/`score_breakdown`/agent score-aggregate fields of the scoring debug API, and the `gossip_positive_score_cap` config field. Grey-listing (thresholds, decay, time-to-whitelisting) is unaffected.
- Removed the `connected_libp2p_peers_average_scores` Prometheus metric (dashboards charting it must drop the panel), and the gRPC `DebugPeer` response no longer populates `ScoreInfo.overall_score` (the proto field is retained for wire compatibility).
- Removed the deprecated `--disable-peer-scorer` flag; peer scoring is always enabled.
- Removed `BadResponses`, chain-status and gossip mirror fields from `peerdata.PeerData` along with the legacy bad-responses, peer-status and gossip scorers.
- Removed the `peers/scorers` package and the `ProcessedBlocks`/`BlockProviderUpdated` fields from `peerdata.PeerData`; the peer store now holds only network bookkeeping.
